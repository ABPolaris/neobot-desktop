# 设置页改造与文案精简 · 变更记录

> 状态：**已实施并验证**（2026-11-16）。本文档保留审核时的判断依据，并附实施结果。

## 1. 需求

1. 顶部导航改为「启动 / 版本 / 设置」；原「下载设置」页变成「设置」，并在其中编辑版本隔离。
2. 设置页的数据目录卡片不再写「所有版本共用同一个数据目录」，改为直接显示当前数据目录的完整路径（含插件、配置所在的位置）。
3. 删掉无用的中文说明。判断标准不是"这条信息对不对"，而是"普通用户读到后会不会做出不同的动作"。示例：*GitHub 分支安装使用该分支自带的 uv.lock，软件包索引不适用于它。* —— 用户既改不了 uv.lock，也管不了软件包索引，这句话只服务于开发者自证。

## 2. 设计判断：一条说明文字什么时候该删

界面里的解释性文字，按五个问题过一遍，任一条不过就删：

| # | 问题 | 不过的典型症状 |
|---|------|----------------|
| 1 | 用户读完能不能做出不同动作？ | 陈述实现机制，用户无从下手 |
| 2 | 说的是用户看得见的现象，还是内部机制？ | 出现 uv.lock、锁文件、包索引、验收流程这类词 |
| 3 | 是否重复了标题、字段名、状态标签已经说过的？ | 卡片叫「下载源」，正文再说一遍"下载源用于……" |
| 4 | 它出现在决策点上，还是常驻在页面上？ | 危险后果写在页面顶部，确认弹窗里反而什么都没有 |
| 5 | 读者是谁？ | 把"进折叠面板的高级用户"才需要的信息摊给所有人 |

两个推论贯穿本次改动：

- **抽象名词换成可操作的事实。** "共用同一个数据目录"是一句概念，用户既看不见也进不去；换成真实路径，用户能打开、能复制、能判断插件装在哪。
- **后果说明搬到决策点。** 版本隔离的影响写在确认弹窗里，卡片正文只留事实。

## 3. 变更一：导航与设置页

### 3.1 导航与路由

- 导航：启动 / 版本 / 设置（原「版本管理」「下载设置」）。图标 `play` / `layers` / 新增的 `settings`。
- 路由：`/settings/downloads` → `/settings`；组件 `DownloadsPage` → `SettingsPage`。
- 三处站内引用同步改：`TitleBar.tsx`、`AppShell.tsx`、`JobCard.tsx`（「更换下载源」）。
- 不加旧路由重定向：应用内没有外部深链，加一条永远走不到的重定向只是死代码。

### 3.2 页面结构

两张卡片，下载源在前 —— 安装失败时 `JobCard` 的「更换下载源」会把人送到这里，落点第一屏就该是它。

```

│  设置                                                      │

│  │ Python 和软件包使用国内镜像；uv 仍从官方源下载。      │   │

│  │ [保存]                                             │   │
│  └────────────────────────────────────────────────────┘   │
│  ┌ 数据目录 ────────────────────────────── 版本隔离 [●] ┐  │
│  │ C:\Users\you\AppData\Roaming\NeoBot\data   [复制]   │  │

│  └────────────────────────────────────────────────────┘   │
└───────────────────────────────────────────────────────────┘
```

页面标题只有「设置」，不再配副标题 —— 两张卡片的标题已经说明了各自范围。

### 3.3 版本隔离与数据目录

- 逻辑不变，只是换了位置：开关 + 确认弹窗，立即生效，不参与「保存」。
- 弹窗文案原样保留（首次启动需要重新配置、现有数据不会复制移动删除 / 独立数据会保留但不再使用）。这是**决策点**上的后果说明，全部通过第 1、4 条。
- 卡片正文只显示真实路径：`Snapshot.DataDir`，前端用等宽字体渲染并带复制按钮。路径随状态变化：
  - 共用模式 → `<数据根目录>\data`
  - 隔离模式、有版本在用 → `<数据根目录>\isolated\<版本号>`
  - 隔离模式、尚未选择版本 → `<数据根目录>\isolated`
  - 「在用」指正在运行的版本，没在运行则取下次启动的版本。
- 禁用态补一句原因（本次唯一新增文案）：运行中「停止 NeoBot 后可修改。」，下载中「下载任务结束后可修改。」——控件变灰却不给理由，是标准可用性缺陷。

### 3.4 版本管理页面的连带调整

- 删掉整个「数据目录」卡片，连同 `SetVersionIsolation` 引入、`toggleIsolation`、`isolationBusy`。
- 可发现性由分支安装卡片承接：共用数据那条路径上写明「建议先备份，或在设置中开启版本隔离」。
- 首页的共用数据警告补一个「去设置」链接，让风险提示有出口。

## 9. 为什么必须补一条变更记录

`AGENTS.md` 的「版本与发布」一节写着：

> 面向用户的变更按 [`.changes/README.md`](../.changes/README.md) 添加变更记录。

`.changes/README.md` 又规定每个文件写一条用户可见的变化，qegg 靠这些文件决定版本号与 CHANGELOG。所以「导航改名 + 隔离开关搬家」这种用户看得见的变化，需要在 `.changes/` 里留下一条，否则这次改动不会出现在发布说明里、也不会触发版本号变化。
